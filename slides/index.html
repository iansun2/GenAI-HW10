動機

為什麼自駕車需要 LiDAR？

相機很便宜，但「看不出距離」。

≈ 90%影像方法：2D 車輛偵測 AP
≈ 15%影像方法：3D 車輛偵測 AP

同樣的影像，在 2D 上找得到車，一旦要在 3D 中標出位置就幾乎失敗（當時的 KITTI 排行榜）。

LiDAR（光達）是什麼？

  • 旋轉的雷射測距儀：量光反射回來的時間 → 算出距離
  • 一次掃描得到大量 3D 點：(x, y, z) + 反射強度
  • 這堆點就叫點雲（point cloud）
  • 直接帶有精確距離，正是 3D 偵測最需要的
3D 物件偵測：在點雲中找出每台車、每個行人，並用一個 3D 框標出位置、大小、朝向。

出處：SECOND §1（引用 KITTI 排行榜）→ wiki/concepts/point-cloud-and-lidar.md · 事實 F01

基礎 1

點雲不是「3D 影像」：三個難搞的特性

想像用很多顆小珠子描出世界的輪廓——近處很密、遠處很稀、中間大部分是空的。

無序

點的排列順序沒有意義，不能像影像一樣直接套 CNN。

稀疏

0.005KITTI 切成 voxel 後「非空格子」的比例

一個場景只有約 5k–8k 個非空 voxel。在空的地方計算 = 浪費。

密度不均

< 10 點遠方車輛常常只剩這麼少 → 容易漏偵測

另外：KITTI 只標註前鏡頭看得到的範圍，只用到約 10% 的點雲。

出處：SECOND §3.1.3、§4.3.1；PointPillars §6 → wiki/concepts/point-cloud-and-lidar.md、sparse-convolution.md · 事實 F02–F04

基礎 2 · 互動

怎麼把點雲變成網路吃得下的東西？

非空格子車輛點示意用合成點雲，非論文數據

Point 直接處理點

最精確，但點多時找鄰居很慢（PointNet 系列）。

Voxel 3D 小方塊

SECOND：0.4 × 0.2 × 0.2 m。規則網格 → 可以做卷積。

Pillar 直立柱子

PointPillars：地面切 0.16 m 格子、高度不切；約 97% 柱子是空的。

拖拉滑桿：格子越小 → 細節越多，但格子數暴增、而且幾乎都是空的。

出處：SECOND §3.1.1；PointPillars §2.1、§4.2 → wiki/concepts/voxelization.md · 事實 F05–F06（左圖為示意）

基礎 3

答案長什麼樣？3D 框與 Anchor

一個 3D 框 = 7 個數字

x, y, z中心 w, l, h大小 θ朝向

Anchor（錨框）＝先擺好的「標準模板」

  • 在鳥瞰圖每個位置擺一個「一般轎車」：1.6 × 3.9 × 1.56 m
  • 網路只需回答：這裡有沒有車？模板要怎麼微調？
  • 朝向小陷阱：θ 和 θ+π 是同一個框（只差車頭車尾）→ SECOND 用 sin(Δθ) 當 loss，再加方向分類器
≈ 70k一個 KITTI 場景裡的 anchor 數
4–6 個每個真實物體配到的正樣本
前景 / 背景極度不平衡 → 使用 focal loss，讓網路專心學「難的、少的」樣本。

出處：SECOND §3.1.5、§3.2.1 → wiki/concepts/anchor-and-box-encoding.md · 事實 F07–F08

基礎 4

怎麼評分？KITTI 這張「考卷」

  • 類別：Car、Pedestrian、Cyclist
  • 難度：Easy / Moderate / Hard（依高度、遮擋、截斷），排行榜看 Moderate
  • 切分：train 3712 / val 3769；test 標註不公開
  • 算對的標準：3D IoU ≥ 0.7（Car）、0.5（Ped / Cyc）
  • AP：precision–recall 曲線下的面積，0–100，越高越好

⚠️ 同一個模型，兩種 AP 算法

R11：11 個 recall 取樣點 · R40：40 個

KITTI 在 2019-10-08 從 R11 改成 R40 → 早期論文和新論文的數字不能直接比。

本簡報的規則：只在「同一張表」裡比大小，並標明 val/test、R11/R40。

求快 · 2018

SECOND：只在「有人的房間」巡邏

比喻：1000 個房間只有 5 間有人。dense 卷積每晚巡完 1000 間；Sparse Convolution 手上有「有人房間清單」，只巡那幾間和鄰居。

  • 一般 sparse conv：資料會往外擴散一圈 → 用來下採樣
  • Submanifold sparse conv：有資料的位置不變 → 用來抽特徵，保持稀疏
  • 結構：Voxel → sparse 3D CNN 壓扁高度 → 2D 鳥瞰圖 → 出框
  • 附送兩個沿用至今的技巧：sin 角度 loss、GT-sampling（把別的場景的車「剪貼」進來）
約 4×訓練加速（vs dense）
約 3×推論加速
KITTI val Car Mod.每幀時間AP
VoxelNet（dense）0.23 s65.46
SECOND0.05 s76.48

求快 · 2019

PointPillars：乾脆把高度拿掉

點雲→切成柱子→每根柱子壓成一個向量→偽影像→2D CNN
  • 3D 卷積仍是 SECOND 的瓶頸 → 只在地面切格子，高度整根算一格
  • 壓成「偽影像」之後，全部只用 2D 卷積，GPU 最擅長
  • val Car Mod.：77.98（和 SECOND 同級）
代價：高度資訊一開始就被壓掉——後面的精度路線都回到 3D voxel。

速度演進（KITTI test 同一張表）

16.2 ms每幀總時間
1.3 msencoder（VoxelNet 要 190 ms）

求準 · 核心概念

一階段 vs 兩階段：先寫草稿，再逐題檢查

One-stage SECOND、PointPillars

Backbone→每個位置直接出框→NMS 去重

Two-stage PV-RCNN、Voxel R-CNN、CasA

Backbone→RPN 粗圈候選框→RoI Pooling：每個框取特徵→精修位置與信心

RoI Pooling：把每個候選框切成 6×6×6 = 216 個格點，逐格收集附近的特徵。難點是 3D 特徵中非空的不到 3%，直接取大多是 0。

80.87 → 84.83PV-RCNN：只有 RPN → 加上第二階段（val R40, Car Mod.）

需要原始點嗎？兩篇相反的答案

PV-RCNN「要，用 point 補精度」

voxel→2048 個 keypoint→RoI 格點

把 voxel、原始點、BEV 特徵先濃縮到 keypoint，再給候選框用。

各模組耗時：VSA（voxel→keypoint）49.4 ms，約佔一半。

Voxel R-CNN「不用，voxel 就夠」

voxel→直接到 RoI 格點

⭐ 主線 · 2022

CasA：精修三次，但 2D 的做法在 3D 不管用

直接套用 2D 的 cascade：Voxel R-CNN 85.27 → 84.82，反而變差。
  • 忽略遠處物體：門檻越提越高，能過關的都是點多的近處車
  • 誤差傳遞：3D 還要估高度和旋轉，小錯一路傳下去
  • 解法：Cascade Attention——每一階段用 attention 讀取所有前面階段的特徵（第三位檢查員手上有前兩位的筆記），最後三階段投票（boxes voting）

進步都在「遠處」

40–50 m45.850.5
50 m 以上7.016.1

KITTI test Car Mod.：81.62 → 83.06

代價：1 階段 64 ms → 3 階段 86 ms

⭐ 主線 · 2025（arXiv 預印本）

NV3D：改的不是 head，是輸入

法向量 = 表面朝哪個方向

  • 對每個 voxel 找 7 個鄰居（KNN），用 PCA 找「最扁」的方向 → 法向量
  • 比喻：米粒撒在桌上，散得很開但沒有厚度——沒有厚度的方向就是法向量
  • 地面的法向量全部朝上 → 可以拿來找出並丟掉多餘的地面
  • 約 90% 的 voxel 在 30 m 以內 → 依距離分環，近處多丟、遠處保留
53.14%兩種取樣合計丟掉的 voxel

新趨勢 · 2023

VoxelNeXt：連偵測頭都 sparse

  • 前面每一篇最後都把特徵轉回完整的 2D 圖才出框——但熱度圖上有反應的位置不到 1%
  • VoxelNeXt：不用 anchor、不用 center、不用 RPN、不用 NMS，直接讓「有資料的 voxel」舉手出框
  • 出框的 voxel 只有 9.9% 在物體中心附近，72.8% 在邊界 → LiDAR 本來就只打到表面，中心不是必要的
FLOPs 只有 CenterPoint 的約 1/5（38.7G vs 186.6G），延遲卻是 66 vs 96 ms——FLOPs ≠ 速度。

偵測範圍越大，差距越明顯

延遲（Argoverse2）50 m200 m
CenterPoint（dense head）82 ms246 ms
VoxelNeXt61 ms66 ms

nuScenes test：CenterPoint 58.0 mAP / 65.5 NDS → VoxelNeXt 64.5 / 70.0

dense 圖的面積隨距離平方成長；sparse 只看有資料的 voxel。

新趨勢 · 2024（arXiv 預印本）

LION：把 Mamba 搬進 3D backbone

怎麼讓 voxel 交流比喻代價
Sparse conv只和隔壁講話看不遠
Transformer小組會議人數的平方
Linear RNN（LION）傳紙條人數的線性
  • 群組大小 4096 / 2048 / 1024 / 512（Transformer 對照組：256）
  • 弱點：排成一維序列，上下相鄰的 voxel 會被拉得很遠 → 加一層 submanifold conv 補回局部資訊
  • 再用自回歸「長出」前景 voxel，補強稀疏

消融（Waymo L2 mAPH）

FLOPs 58.5G（DSVT-Voxel 100.8G），但沒有報告延遲；作者承認 linear RNN 平行化不如 Transformer，速度仍需改進。

出處：LION §3、§4.2、§5、Table 5、Table 12 → wiki/papers/lion.md、concepts/transformer-and-linear-rnn-backbone.md · 事實 F42、F44、F45

總結

一張圖記住：每一步都在問「哪裡在浪費？」

表示法

  • SECOND：空白不算
  • PointPillars：高度不算
  • NV3D：多餘的地面不算

精修

  • PV-RCNN：用 point 精修
  • Voxel R-CNN：voxel 就夠，快 3 倍
  • CasA：精修三次，救回遠處

架構

  • VoxelNeXt：連 head 都 sparse
  • LION：用 linear RNN 看得更遠
  • 兩者都提醒：FLOPs ≠ 速度
