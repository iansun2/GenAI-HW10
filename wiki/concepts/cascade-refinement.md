# Cascade Refinement（多階段串接精修）

## 白話解釋（給初學者）

[Two-stage](one-stage-vs-two-stage.md) 偵測器是「先粗圈，再精修一次」。
**Cascade（串接）**是「精修好幾次」：第一次修完的框交給第二位檢查員，第二位修完再交給第三位，而且每一位的標準越來越嚴格。

比喻：寫報告時先自己改一次，再請同學改，最後請老師改，每一輪都在前一輪的版本上修，要求也越來越高。

## 傳統 Cascade（2D 的 Cascade R-CNN）

- 串接 Nr 個精修頭，第 j 個精修頭以第 j−1 個的輸出框為輸入（CasA Eq. 1）。
- 每個階段的正樣本 IoU 門檻逐步提高，讓後面的階段專門處理「已經很接近」的框。
- 在 2D 影像偵測中效果很好（CasA §II-B）。

## 為什麼直接套用到 3D 會失敗（[CasA](../papers/casa.md) §III-A1）

實驗：在 [Voxel R-CNN](../papers/voxel-rcnn.md) 上加傳統 cascade（KITTI val R40, Car Mod., CasA Table I）：
- 原本：85.27
- 3 個階段後：**84.82，反而下降**

兩個原因：
1. **忽略遠處物體**
   - LiDAR 點雲近密遠疏。
   - 門檻提高後，能通過的正樣本多半是點多的**近處**物體 → 後面的階段很少看到遠處物體，學不會處理它們。
2. **誤差傳遞**
   - 3D 框要估高度和非軸對齊的旋轉角，比 2D 更難。
   - 前一階段的小錯誤會一路傳下去，後面的階段無法修正。

## CasA 的解法

| 問題 | 解法 | 直覺 |
|---|---|---|
| 後面的階段看不到遠處物體 | **Cascade Attention**：每個階段都用 attention 讀取**所有前面階段**的 RoI 特徵 | 第三位檢查員手上有前兩位的所有筆記 |
| 誤差一路傳遞 | 階段之間的 attention 連結，加上測試時的 **Boxes Voting**（依信心分數加權平均各階段的框） | 三位檢查員投票，不只聽最後一位 |

- 效果（CasA Table VIII，val R40, Car Mod.）：傳統 cascade 84.82 → 加 CAM 85.72 → 加 part-aided scoring 85.85 → 加 voting 86.37。
- 遠距離（CasA Fig. 5）：50 m 以上從 7.0 提升到 16.1；近距離幾乎不變。→ 證實解決了「忽略遠處物體」的問題。

## 階段數的取捨（CasA Table VI）

| 階段數 | Car Mod. (val R40) | 執行時間 |
|---|---|---|
| 1 | 85.49 | 64 ms |
| 3 | 86.37 | 86 ms |
| 5 | 86.24 | 114 ms |

- 3 個階段以後就不再進步，只會變慢。

## 出現在哪些論文

- [CasA](../papers/casa.md)：第一個在完全監督的 3D 偵測中做出有效 cascade 的方法（論文自述，§II-B）。

## 常見誤解

- 「精修越多次越好」→ CasA Table VI：4、5 個階段都比 3 個差，而且每多一階段多約 13–15 ms。
- 「2D 有效的方法，3D 一定也有效」→ 傳統 cascade 在 3D 反而變差，因為 3D 點雲有**近密遠疏**的特性。
